# AI 视频聚合平台设计规范

- 日期：2026-08-28
- 状态：已确认
- 项目目录：`D:\AI视频聚合平台`
- 目标市场：中国大陆
- 上线形态：公开商业 Web 平台

## 1. 目标

建设一个可直接上线运营的 AI 视频 API 聚合平台。平台接入不同供应商的视频生成 API，向终端用户提供统一的网页生成体验，并向运营团队提供完整管理后台。

平台的核心能力是：

1. 用统一的能力模型描述不同供应商、模型和参数。
2. 根据模型能力动态生成用户表单，不把页面写死在某个供应商协议上。
3. 同时提供智能路由和专业模型选择两种生成模式。
4. 使用平台点数完成充值、预冻结、结算、退款和审计。
5. 对供应商成本、销售收入、毛利、余额和健康状态进行运营管理。
6. 通过微服务、事件驱动、幂等、对账、监控和灾备保证生产可靠性。
7. 以较低云资源规格上线，在不改变架构和代码的情况下扩容至目标负载。

本项目不采用功能缩水的 MVP 交付方式。前期仅缩小云资源规格，不缩减已确认的产品功能、财务控制、安全措施和运维能力。

## 2. 已确认的产品决策

| 主题 | 决策 |
|---|---|
| 商业模式 | 公开商业平台，用户充值并按任务消耗点数 |
| 市场 | 中国大陆，人民币结算 |
| 用户入口 | 仅 Web 用户端，不向客户开放平台 API |

| 生成能力 | 供应商支持什么能力，平台就通过动态 Schema 展示什么能力 |
| 模型选择 | 智能模式自动路由；专业模式手动选平台和模型 |

## 3. 范围边界

### 3.1 用户端范围

#### 官网与转化

- 首页：核心卖点、热门模型、案例作品、开始生成入口。
- 模型广场：按平台、模型、能力、价格、速度和运行状态筛选。
- 价格中心：点数说明、模型计费规则和充值套餐。
- 帮助中心：教程、常见问题、公告、服务协议和隐私政策。

#### 账号与安全

- 手机号短信验证码注册和登录。
- 头像、昵称、手机号换绑。
- 登录设备和会话管理。
- 退出全部设备和账号注销。
- 验证码、登录和敏感操作的限流与风控。

#### AI 视频生成工作台

- 智能模式：用户选择质量、速度、预算和目标，平台自动选择模型。
- 专业模式：用户手动选择供应商、模型和完整参数。
- 动态能力表单：支持文生视频、图生视频、首尾帧、参考视频、视频延长等供应商声明的能力。
- 动态字段支持默认值、枚举、条件显示、字段依赖、单位、范围、帮助文案和文件限制。
- 提交前展示模型、关键参数、预计点数和退款/取消规则。
- 图片和视频素材通过 OSS 直传，展示上传进度并校验格式和大小。
- 防止重复点击、刷新和网络重试造成重复任务或重复扣点。

#### 任务中心

- 状态：排队、提交中、生成中、成功、失败、取消、过期、已结算、已退款。
- 任务详情：参数快照、模型、费用、时间线、失败原因和任务编号。
- 操作：取消、复制参数、重新生成、删除历史记录；可用性取决于任务状态和供应商能力。
- 按状态、时间、模型、生成方式和任务编号查询。
- 使用 SSE 推送状态变化，断线时自动重连，并以轮询作为降级方案。

#### 作品与素材库

- 作品预览、下载、重命名、删除和筛选。
- 上传素材的复用、删除和容量统计。
- 使用私有 OSS、短时签名链接、CDN 防盗链和生命周期规则。
- 将供应商结果立即转存 OSS，不依赖可能过期的供应商临时链接。

#### 点数、订单和发票

- 钱包展示可用点数、冻结点数、累计充值和累计消费。
- 微信支付购买点数套餐。
- 展示充值、冻结、结算、退款和后台调整的不可变交易流水。
- 展示充值订单和支付凭证。
- 支持发票申请、审核状态和已开票记录；本次不集成第三方电子税务开票 API。

#### 消息与服务

- 站内消息：任务结果、支付结果、余额预警和系统公告。
- 工单：问题、附件、回复、状态和满意度。
- 模型效果、失败任务和产品建议反馈。

### 3.2 运营管理后台范围

#### 经营总览

- 注册、活跃、充值、消费、任务量、成功率、平均生成时长和队列积压。
- 收入、供应商成本、毛利、毛利率、客单价和复购。
- 供应商余额、失败率、支付异常和服务告警。

#### 用户运营

- 用户搜索、详情、状态、登录设备、登录记录、封禁和解封。
- 钱包余额、冻结、充值、消费和调整历史。
- 人工加减点数要求权限、原因、二次确认和审计；正式上线默认全部要求双人复核。
- 用户标签、注册来源、消费等级、筛选和导出。

#### 供应商与密钥

- 供应商名称、接口地址、鉴权、回调、维护窗口和启停状态。
- 密钥加密、脱敏、轮换、作用范围和访问审计。
- 采购折扣、供应商点数余额、成本单位和余额阈值告警。
- 成功率、延迟、限额、熔断、恢复和健康检查。

#### 模型与能力中心

- 供应商模型映射、展示名称、说明、封面、排序和上下架。
- 动态能力 Schema 的字段、依赖、校验、默认值和 UI 提示。
- 配置草稿、校验、发布、历史版本、差异和回滚。
- 历史任务永久引用提交时的配置版本和参数快照。

#### 定价与智能路由

- 按模型、时长、分辨率和参数计算供应商成本。
- 固定点数、成本加成、阶梯价格和生效时间。
- 质量、速度、价格权重，供应商优先级和故障降级。
- 最低毛利率、成本变化告警和亏损模型自动停售。
- 路由决策必须保存候选集合、评分和最终选择原因。

#### 任务运营

- 全量任务检索、参数快照、时间线和标准化供应商响应。
- 原始供应商请求与响应仅对授权管理员展示，并进行密钥和敏感字段脱敏。
- 重试、切换、终止、补偿和人工退款。
- 队列并发、优先级、限速、暂停、恢复和积压监控。
- 归档供应商审核失败原因；不提供平台人工内容复审流程。

#### 财务、支付和发票

- 充值订单、支付回调、关闭、退款和异常订单。
- 点数总账、冻结、结算和退款一致性检查。
- 微信支付渠道账单获取或导入、差异发现和处理。
- 按用户、模型、供应商和时间统计成本、收入和毛利。
- 发票申请、审核、开票信息和记录。

#### 内容与客户运营

- 充值套餐的面额、赠送点数、限购、有效期和上下架。
- Banner、热门模型、案例、公告和帮助文档。
- 站内信和短信模板及触发规则。
- 工单分配、回复、内部备注、状态和满意度。

#### 后台账号和系统治理

- 超级管理员。
- 自定义权限点、角色、后台用户和数据范围。
- 管理员登录强制双因素认证。
- 登录、配置、财务、权限和敏感操作审计。
- 短信、支付、OSS、CDN、回调域名和功能开关配置。
- 服务、日志、指标、链路、告警和发布状态。

### 3.3 明确不在本次范围内

- 面向客户的开放 API。
- iOS 或 Android 原生应用。
- 海外支付、多币种和国际化运营。
- 会员订阅体系。
- 团队或企业工作空间。
- 平台自建文本、图片或视频内容审核。
- 本地 AI 推理、模型训练或 GPU 渲染。
- 在线视频编辑器。
- 社区发布、关注、评论和社交互动。
- 第三方电子税务开票 API。

新增上述范围需要单独设计、评估和确认，不得以小改动形式隐式加入。

## 4. 技术架构

### 4.1 技术选择

- 语言：TypeScript；Node.js 使用实现阶段的受支持 LTS，并在仓库中固定版本。
- 用户端和后台：两个独立 Next.js 应用。
- 服务端：NestJS 微服务。
- API：外部 REST/JSON，使用 OpenAPI 3.1；任务状态使用 SSE，轮询降级。
- 事件：阿里云 RocketMQ 5.x Serverless。
- 数据库：阿里云 RDS PostgreSQL 高可用版。
- 缓存、限流和分布式锁：阿里云 Tair 高可用版。
- 文件：阿里云 OSS 私有 Bucket + CDN。
- 容器：Docker、ACR、ACK 托管版 Pro + Auto Mode。
- 配置与密钥：阿里云 KMS 和 ACK Secret Manager。
- 可观测性：OpenTelemetry、SLS、ARMS/APM 和云监控。
- 基础设施：Terraform 和 Helm。
- 仓库：pnpm workspace 管理的 TypeScript monorepo；每个服务仍是独立构建和部署单元。

## 5. 微服务和数据所有权

| 服务 | 职责 | 独占数据 |
|---|---|---|
| identity-service | 用户、短信登录、会话和设备 | 用户账号、会话、设备、登录记录 |
| iam-service | 后台用户、角色、权限和审计 | 管理员、角色、权限、数据范围、审计日志 |
| catalog-service | 供应商、模型和能力版本 | 供应商档案、模型目录、能力 Schema 和发布版本 |
| quote-routing-service | 报价、路由和利润保护 | 定价规则、路由规则、报价快照和路由决策 |
| generation-service | 生成任务和状态机 | 任务、参数快照、状态迁移和用户可见错误 |
| provider-runtime | 供应商协议执行 | 供应商执行记录、外部任务 ID、原始响应摘要和重试状态 |
| wallet-service | 点数账本 | 钱包账户、不可变分录、余额快照和对账结果 |
| payment-service | 微信支付、渠道对账和发票流程 | 充值/退款订单、回调事件、渠道对账、发票申请和状态 |
| asset-service | OSS 资产 | 作品、素材、文件元数据和生命周期状态 |
| operations-service | 运营内容和客户服务 | 套餐、Banner、公告、帮助、工单和反馈 |
| notification-service | 站内信和短信 | 模板、发送任务、送达状态和重试记录 |
| reporting-service | 经营报表 | 由领域事件构建的只读统计模型 |

前期所有 PostgreSQL 数据库位于一个 RDS 高可用物理集群内，以控制费用；每个服务使用独立 Database、独立账号和独立迁移。禁止跨服务数据库查询和跨库 Join。服务只能通过公开 API 或事件使用其他领域的数据。未来可将任何 Database 迁移到独立实例而不改变服务契约。

Tair 只保存可重建的缓存、限流、锁和短期状态，不作为钱包、支付或任务事实来源。

## 6. 服务通信和一致性

### 6.1 通信原则

- 浏览器到平台：REST/JSON 和 SSE。
- 必须即时返回的内部查询或命令：ACK 私网 HTTP，必须配置超时、有限重试和熔断。
- 跨领域状态传播：RocketMQ 领域事件。
- 每个请求和消息携带 Trace ID、Correlation ID 和业务幂等键。
- 事件 Schema 版本化；消费者必须兼容当前和前一兼容版本。

### 6.2 可靠消息

每个产生事件的服务使用 Transactional Outbox：领域数据和 Outbox 记录在同一数据库事务中提交，发布器再将事件发送至 RocketMQ。消费者使用 Inbox/Processed Message 表去重。该组合保证消息可以重复投递，但业务效果只发生一次。

不使用跨服务分布式数据库事务。需要跨服务完成的流程使用 Saga 和补偿操作，例如任务创建失败后释放冻结点数。

## 7. 动态模型能力

### 7.1 Canonical Capability Schema

平台使用 JSON Schema Draft 2020-12 作为动态能力的规范表示，并附加独立 UI Schema。能力 Schema 必须支持：

- 生成方式和模型版本。
- 文本、数字、布尔值、枚举、对象、数组和文件引用。
- 必填、默认值、范围、长度、正则、枚举和组合约束。
- 字段依赖、条件显示和互斥字段。
- 单位、标签、帮助文案、示例、排序和分组。
- 图片/视频文件格式、大小、尺寸、时长和数量限制。
- 哪些字段影响成本、路由和供应商请求。

同一 Schema 驱动用户表单、服务端校验、报价输入和适配器映射。服务端必须再次校验，不能信任浏览器结果。

Schema 使用草稿、校验、发布、历史版本和回滚流程。已发布版本不可修改，只能发布新版本。任务保存版本 ID 和完整参数快照。

### 7.2 供应商适配器接口

每个供应商适配器实现统一接口：

```ts
interface VideoProviderAdapter {
  validateConfiguration(): Promise<ValidationResult>;
  getHealth(): Promise<ProviderHealth>;
  createTask(input: CanonicalCreateTask): Promise<CreateTaskResult>;
  queryTask(input: CanonicalQueryTask): Promise<QueryTaskResult>;
  cancelTask?(input: CanonicalCancelTask): Promise<CancelTaskResult>;
  verifyCallback(input: RawCallback): Promise<VerifiedCallback>;
  normalizeCallback(input: VerifiedCallback): Promise<CanonicalTaskEvent>;
  getBalance?(): Promise<ProviderBalance>;
}
```

适配器还要提供：

- 能力 Schema 和 UI Schema。
- 供应商字段映射。
- 标准错误码映射。
- 成本计算规则。
- 限流、重试和熔断策略。
- 回调验签和去重规则。
- 用于契约测试的脱敏请求/响应样例。

不同供应商适配器作为独立 package 和独立 Worker Deployment 运行，避免单个供应商故障影响全部通道。

`cancelTask` 仅在供应商真实支持取消时实现；未实现时，平台在供应商受理后不展示取消按钮，不能用本地改状态伪装远端取消成功。

当前未指定首个真实供应商。平台核心开发使用可控的 Mock Provider 完成全链路测试。生产上线的必要条件是至少一个真实供应商适配器在获得文档、测试密钥和生产密钥后通过准入套件；每个新增供应商单独形成接入记录和验收证据。

## 8. 智能路由和专业模式

### 8.1 智能模式

路由依次执行：

1. 根据生成方式和参数筛选能力匹配的模型。
2. 排除下架、维护、熔断、欠费、限额或健康不达标的通道。
3. 计算供应商采购成本、用户售价和毛利率。
4. 根据用户的质量、速度、预算偏好和后台权重评分。
5. 执行最低毛利率保护。
6. 保存候选项、评分、排除原因和最终选择。

### 8.2 专业模式

专业模式严格使用用户选择的平台和模型。除非用户在提交前明确允许“同等能力故障切换”，平台不能静默更换模型。参数和能力必须以提交时发布版本为准。

### 8.3 故障切换

只有在以下条件全部满足时才能自动切换：

- 原供应商明确未受理，或明确确认未计费。
- 备用模型满足相同能力和关键参数。
- 备用售价不超过用户确认报价。
- 专业模式用户允许切换，或处于智能模式。
- 切换决策被完整审计。

供应商已经受理但结果未知时，禁止盲目重复提交到另一供应商。

## 9. 生成任务和点数闭环

### 9.1 报价

- 报价包含 Quote ID、用户 ID、模型或候选集合、能力版本、参数摘要、销售点数、成本估计、规则版本和过期时间。
- Quote 默认十分钟有效；过期必须重新报价。
- 用户最终扣点不得超过已确认报价，除非重新展示报价并再次确认。

### 9.2 提交和冻结

1. Gateway 校验客户端幂等键。
2. generation-service 校验 Quote、用户和参数快照。
3. wallet-service 原子检查余额并将预计点数从可用转为冻结。
4. generation-service 创建任务并写 Outbox。
5. 若任务创建最终失败，Saga 请求 wallet-service 释放冻结。

### 9.3 状态机

```text
QUOTED -> RESERVED -> QUEUED -> SUBMITTING -> RUNNING
RUNNING -> SUCCEEDED | FAILED | CANCELED | EXPIRED
SUCCEEDED -> SETTLED
FAILED | CANCELED | EXPIRED -> REFUNDED 或按取消规则 SETTLED
```

每次迁移包含旧状态、新状态、原因、来源、操作者、时间、版本号和 Trace ID。使用乐观锁阻止并发乱序迁移。终态只能通过显式补偿流程改变。

### 9.4 成功结算

1. provider-runtime 校验结果 URL、类型、大小和完整性。
2. asset-service 将文件立即转存私有 OSS 并创建作品记录。
3. wallet-service 将实际消费从冻结转入平台消费账户，并释放差额。
4. reporting-service 记录供应商成本、折扣、用户收入、毛利和毛利率。
5. notification-service 通知用户。

### 9.5 失败和取消

- 供应商失败：用户冻结点数全额退回；供应商可能产生的失败成本由平台承担。
- 供应商受理前取消：全额退回。
- 供应商受理后：仅当供应商支持取消时展示取消操作；按照提交前公示并保存到任务快照的取消规则处理。
- 供应商无法确认取消或仍会计费时，平台不能承诺全额退款；UI 必须在提交前展示该规则。
- 所有退款都是新账本分录，禁止修改或删除原消费分录。

## 10. 点数账本和支付

### 10.1 点数账本

wallet-service 使用不可变、平衡的复式分录模型。账户至少包括：

- 用户可用点数。
- 用户冻结点数。
- 平台点数负债。
- 平台已消费点数。
- 活动赠送和管理员调整账户。

每个账本事务借贷合计必须相等，并有唯一业务键。余额是分录的事务性快照，必须能够由账本重建。任何服务和管理员都不能直接更新余额字段。

核心不变量：

```text
初始余额 + 累计入账 - 累计消费 = 可用余额 + 冻结余额
```

用户点数账本和供应商采购成本账本分开，避免将不同计价单位混合。

### 10.2 微信支付

- 使用微信支付 API v3 适配器。
- 创建平台订单后再创建微信支付单。
- 回调必须验签、校验商户号、金额、币种和订单状态。
- 重复回调和主动查询只能让订单入账一次。
- 每日执行渠道账单与平台订单对账。
- 商户号开通前仅启用测试支付和有审计的后台人工加点，不模拟真实到账。

## 11. 文件和视频存储

- 浏览器使用受限的预签名凭证直传 OSS，业务服务不代理大文件。
- 上传前申请会话，限制 MIME、扩展名、魔数、大小、数量和有效期。
- OSS Bucket 私有，下载使用短时签名 URL 或 CDN 鉴权 URL。
- 供应商结果由 Worker 流式转存 OSS，禁止将完整视频写入容器本地磁盘。
- 原始上传、生成成品、封面和临时文件使用不同前缀和生命周期。
- 删除使用软删除窗口和异步物理清理，保证数据库和 OSS 状态一致。
- 对用户展示容量和保存策略。

## 12. 安全设计

### 12.1 身份与权限

- 用户短信验证码有手机号、IP、设备和时间窗口限流。
- 用户短期 Access Token + 可轮换 Refresh Token；会话可以按设备撤销。
- 后台管理员使用独立登录域和独立会话，强制双因素认证。
- 后台 RBAC 支持权限点、角色、用户和数据范围。
- 高风险操作二次确认。人工加减点数默认全部要求双人复核；运营方可在正式运营后根据审计结果设置非零免复核阈值。

### 12.2 密钥与数据

- 供应商、微信支付、短信、OSS 和数据库凭据存入 KMS。
- ACK 工作负载按服务身份动态读取凭据，遵守最小权限。
- 密钥支持轮换；后台只显示脱敏值。
- 日志不得记录验证码、密钥、完整支付敏感数据或未经授权的原始用户素材。
- 数据传输使用 TLS，存储使用云产品静态加密。

### 12.3 应用和网络

- HTTPS、HSTS、CSP、CSRF、CORS 和安全 Cookie。
- WAF、Gateway 限流、请求大小限制和异常流量阻断。
- 数据库、Tair、RocketMQ 和 OSS 管理接口仅走 VPC 或受控私网。
- Provider Worker 配置出站域名白名单，防止 SSRF。
- 容器非 root、只读根文件系统、资源限制、镜像扫描和签名。

### 12.4 内容安全边界

平台依赖供应商审核并保存标准化失败原因，不建设平台二次审核。公开运营前，运营方仍需自行完成适用的备案、协议、隐私和内容合规评估。

## 13. 错误处理和可靠性

### 13.1 错误分类

| 类型 | 示例 | 处理 |
|---|---|---|
| 用户/业务错误 | 参数错误、余额不足、模型下架 | 不重试，返回稳定错误码和修复提示 |
| 临时技术错误 | 网络超时、429、部分 5xx | 幂等重试、指数退避、抖动、最大次数 |
| 不可恢复错误 | 密钥失效、供应商欠费、协议破坏 | 停用通道、告警、安全切换或退款 |
| 未知错误 | 未分类异常 | 记录 Trace、进入死信、人工调查，禁止无限重试 |

重试超过上限进入死信队列。运营后台可以查看、重放或关闭死信，但重放前必须再次执行幂等和计费安全检查。

### 13.2 自动修复和对账

- 每分钟扫描卡住、超时和回调缺失任务。
- 每小时核对钱包冻结、任务终态、结算和退款。
- 每日核对微信支付账单、充值订单和点数入账。
- 每日扫描孤儿 OSS 对象、过期临时素材和异常容量。
- 能确定正确结果时自动修复；无法确定时创建后台事件等待人工处理。

### 13.3 服务目标

- 核心平台 API 月度可用性：99.9%，不把外部 AI 供应商生成时长和可用性计入平台 SLO。
- 钱包和支付：账本不平数量必须为零。
- RPO：不超过 5 分钟。
- RTO：不超过 60 分钟。
- 普通查询 API：目标负载下 p95 小于 500 ms。
- 任务受理 API：目标负载下 p95 小于 2 秒，不包含供应商生成时间。
- 平台自身非预期错误率：目标负载下低于 0.5%。

RPO/RTO 适用于交易数据库、任务元数据、配置和点数账本。生成视频和用户素材默认保存在单地域 OSS；若要求区域级灾难下也满足相同 RPO/RTO，必须开启 OSS 跨区域复制并单独计入存储和流量预算。

## 14. 可观测性和告警

### 14.1 观测数据

- JSON 结构化日志，包含 Trace ID、Task ID、User ID 和标准错误码。
- RED 指标：请求率、错误率和延迟。
- USE 指标：资源利用率、饱和度和错误。
- RocketMQ 队列深度、消费滞后、重试和死信。
- 任务成功率、生成时长、供应商健康、余额和限流。
- 充值成功率、退款率、账本一致性、成本和毛利。
- 浏览器、Gateway、微服务、消息和供应商调用的全链路追踪。

### 14.2 告警等级

- P0：账本不平、重复扣款、数据泄露、全站不可用。立即自动止损并电话/短信告警。
- P1：支付大面积失败、核心队列停滞、数据库主备异常。十分钟内响应。
- P2：单一供应商异常、失败率升高、余额不足。自动熔断并由运营处理。
- P3：容量趋势、低毛利和非关键报表异常。进入计划维护队列。

每个 P0/P1/P2 告警必须关联 Runbook、负责人和关闭条件。

## 15. 阿里云部署

### 15.1 生产拓扑

- ACK 托管版 Pro + Auto Mode。
- 至少两个可用区。
- CDN/WAF/ALB 统一入口。
- 核心无状态服务至少两个副本，配置 Pod 反亲和和 PodDisruptionBudget。核心服务指 `edge-gateway`、`identity-service`、`catalog-service`、`quote-routing-service`、`generation-service`、`wallet-service` 和 `payment-service`；可重放事件的辅助服务允许一个常驻副本并由 ACK 自动拉起。
- Provider Worker 按供应商分 Deployment，通过 KEDA 按消息积压扩缩容。
- API 服务使用 HPA 按 CPU、延迟或 QPS 扩缩容。
- Auto Mode 在 Pod 无法调度时增加节点。
- RDS PostgreSQL 高可用，Tair 高可用，RocketMQ 5.x Serverless 使用 VPC 私网连接。
- ACR 保存经过扫描和签名的容器镜像。

### 15.2 成本策略

爬坡期让多个独立微服务共享少量 ACK 节点；独立部署和数据边界不变。数据库先共享一个高可用物理 RDS 集群。RocketMQ 使用 Serverless 按量计费。OSS、CDN、短信和额外 Worker 随业务用量增长。

爬坡期基础云资源目标为每月 2,000～3,500 元。达到 1 万注册用户和 200 个并发任务时，预计基础云资源增长至每月约 6,000～10,000 元。200 个并发任务表示平台可稳定受理和跟踪 200 个异步任务；实际同时提交到某个供应商的数量仍受该供应商配额和限流策略约束。两组估算均不包含 AI 供应商点数、视频 CDN 流量、短信和微信支付手续费，最终以部署时阿里云控制台报价为准。

### 15.3 发布

- 本地使用 Docker Compose 启动基础依赖和 Mock Provider。
- CI 构建一次镜像，测试通过后在环境间晋级同一制品。
- 预发布使用独立命名空间、数据库和 OSS 前缀，禁止复制生产敏感数据。
- 生产使用灰度或滚动发布，健康指标不达标自动回滚。
- 数据库迁移必须向前兼容，应用回滚时旧版本仍可运行。

## 16. 备份和灾备

- RDS 高可用、自动备份和时间点恢复，备份策略满足 RPO 目标。
- 重要数据库定期跨地域备份。
- 作品和素材 Bucket 开启版本控制并保留七天误删恢复窗口；临时上传在二十四小时后清理，失败任务临时文件在七天后清理。关键配置和不可重建资料采用跨地域复制；大体积视频默认不跨地域复制，以遵守前期预算。
- Terraform 和 Helm 定义全部可重建基础设施。
- 每季度执行数据库恢复演练。
- 每次重大基础设施变更后验证集群重建、密钥恢复和应用回滚流程。
- 恢复演练必须记录实际 RPO、RTO、失败点和改进项。

## 17. 测试策略

### 17.1 自动化测试

- 单元测试：状态机、定价、路由、权限和错误映射。
- 属性测试：账本守恒、幂等、终态不可非法迁移等不变量。
- 集成测试：真实 PostgreSQL、Tair 和容器化依赖，不只 Mock 数据库。
- 契约测试：前端/API、服务 API、事件 Schema 和供应商样例。
- 端到端测试：注册、测试充值、生成成功/失败/取消/退款、后台定价和权限。
- 动态表单测试：Schema 渲染、条件字段、文件限制、服务端校验和版本回滚。

核心 `wallet-service`、`payment-service` 和 `generation-service` 领域规则覆盖率目标不低于 95%；项目整体覆盖率不低于 80%。覆盖率不能替代场景和不变量测试。

### 17.2 供应商适配器准入

每个适配器必须通过：

- 能力 Schema 校验。
- create/query/cancel/callback 协议映射。
- 鉴权、验签和密钥脱敏。
- 标准错误映射。
- 幂等、重复回调、乱序、限流、超时、重试和熔断。
- 结果 URL 过期、类型错误、大小异常和 OSS 转存。
- 成本、折扣和毛利计算样例。
- 供应商沙箱真实小额任务。

### 17.3 性能和稳定性

- 模拟 1 万注册用户和 200 个并发异步生成任务。
- 持续压测、突发压测和 24 小时长稳测试。
- 验证 HPA、KEDA 和节点自动扩容。
- 验证没有任务永久卡住、连接泄漏、内存泄漏和账本累计误差。

### 17.4 故障演练

- 杀死 API 或 Worker Pod。
- 供应商 429、5xx、超时、回调丢失和乱序。
- 供应商余额耗尽、密钥失效和协议字段变化。
- Tair 重启、消息重复投递和消费暂停。
- RDS 主备切换和连接中断。
- OSS 上传/下载失败和临时链接过期。
- 微信重复、延迟回调和渠道账单差异。
- 从备份恢复数据库并验证 RPO/RTO。
- 发布失败和版本回滚。

## 18. CI/CD 和上线门禁

发布流水线顺序：

1. 格式、Lint 和 TypeScript 类型检查。
2. 单元、属性和组件测试。
3. 集成、契约和端到端测试。
4. 数据库迁移验证。
5. SAST、依赖、Secret 和容器镜像扫描。
6. 制品签名并推送 ACR。
7. 预发布部署和冒烟测试。
8. 生产灰度，自动观测错误率、延迟、账本和任务指标。
9. 健康门禁通过后全量；失败自动回滚。

正式上线必须同时满足：

- 所有 P0/P1 缺陷关闭。
- 核心商业流程无已知高风险缺陷。
- 钱包、支付和任务对账连续通过且差异为零。
- 目标压测、长稳测试和关键故障演练通过。
- 备份已证明可以恢复。
- 监控、告警、值班、恢复和回滚 Runbook 可用。
- 微信商户、短信签名、域名和适用备案就绪。
- 至少一个真实供应商生产适配器通过准入测试。

以下任一情况禁止上线：

- 重复扣点、账本不平或支付无法对账。
- 供应商异常可能造成无限重试或重复采购。
- 备份未验证恢复。
- 管理员权限或供应商密钥存在越权泄露路径。
- 核心告警无人接收或缺少处置步骤。

## 21. 变更控制

本规范是后续实施计划、任务拆分和验收的范围基线。新增功能、改变财务规则、改变内容安全责任或改变已确认的服务边界时，必须先更新本规范并获得确认。供应商适配器可以按既定接口独立增加，但能力、成本、退款或协议存在新语义时，需要为该适配器补充专项设计和验收记录。
